# Codex Session Cleaner

Windows 本地 Codex 会话管理与清理工具。Python 3.10+、标准库后端、中文 Web 界面，无需 `pip install`、Node.js 或外部数据库。仅监听 `127.0.0.1`，不上传会话内容。

## 启动

双击 **start.cmd**，浏览器会自动打开。保留启动窗口；关闭窗口即停止服务。默认端口 8765 被占用时自动分配空闲端口，以启动窗口中的地址为准。

也可以在项目目录运行：

```powershell
python app.py
python app.py --home "D:\我的数据\Codex" --cli "C:\安装目录\codex.exe"
python app.py --port 8766 --no-browser
```

支持 `CODEX_HOME`、`CODEX_CLEANER_CLI` 环境变量。页面「设置与诊断」可切换数据目录、CLI 并重新检测；页面设置只在本次运行生效，不修改 Codex 配置。

## 使用

1. 等待扫描完成。默认按大小倒序显示用户主对话，可搜索标题、项目、路径和 ID，按项目筛选或按最后活动排序。点击「按项目分组」可切换分组视图：项目显示当前筛选结果的会话数量、总占用和工作目录，支持折叠及整组勾选。按体积排序时，项目按总占用排序、组内按会话大小排序；按最后活动排序时，项目按组内最新活动时间排序。分组开关会在当前浏览器中记住。优先按 Codex 项目 ID 分组，没有项目 ID 时按完整工作目录分组，不会合并同名但不同路径的项目。
2. 点击标题查看用户输入、最终回复及关联文件。预览按需分页，图片为占位信息。
3. 勾选会话，查看已选数量、预计空间及删除计划。选择跨筛选条件保留，底栏计数包含所有已选项。
4. **无需退出 Codex。** 选择“未占用”的会话，确认计划中的标题、ID、文件数量及可能连带删除的子会话，点击「永久删除 N 个会话」。单选、多选均只需确认一次，不用输入文字。当前会话、占用中和状态未确认的目标禁止删除。
5. 查看每个会话的成功、部分完成或失败结果，列表会自动更新。残留路径与归属证据会显示在结果中，不会被工具擅自删除。

从 Codex 内启动工具时，继承的 `CODEX_THREAD_ID` / `CODEX_SESSION_ID` 对应会话在本次服务生命周期内始终受保护。独立双击启动不继承这些 ID，但仍检查每个目标的官方写入锁，不会因为其他 Codex 会话在运行就全部禁止删除。

## 数据来源和空间口径

- 列表使用本机 `state_*.sqlite` 中 `threads`、项目和子代理关系元信息，以 `mode=ro`、`query_only` 查询，保留 WAL 可见性。最高版本数据库结构不兼容时明确报错，不猜测格式。
- 名称优先 `threads.name`，其次 `title`、`first_user_message`，再有限读取用户消息。过滤已识别的注入指令包装，不因标题仅含 `AGENTS.md` 字样就隐藏整个会话。缺失时展示 ID 标识。
- `source`、`thread_source`、子代理关系和 `agent_path` 区分用户主对话、内部线程与未知来源。后两类只出现在高级视图；未知来源禁止删除。旧版元信息可能与桌面端实际可见列表不同。
- 扫描 `sessions/`、`archived_sessions/` 的文件属性和最多 **256 KiB 文件头**。以 `session_meta.payload.id` 和数据库 `rollout_path` 交叉确认，**不用文件名 UUID、session_id 或 parent_thread_id 推断所有权**。支持 Windows `\\?\` 长路径形式。
- 同一线程多个文件聚合。重复路径去重；共享引用、头部冲突、硬链接不计入独占空间并阻止相关删除。越界路径和无法安全归属的文件进入独立诊断区。
- 「会话文件大小」与「预计最多释放」均为可确认独占 JSONL 的**逻辑字节数**。顶部占用涵盖主对话与内部记录的已确认独占文件；搜索筛选不改变此全局数字。紧凑状态条的“当前会话 / 当前内部记录”数量则跟随当前视图、搜索与项目筛选，包含归档记录；折叠项目不改变计数。共享文件、SQLite、WAL、图片附件、数据库空闲页均不均摊。实际磁盘可用空间变化可能受压缩、稀疏文件、并发写入影响。
- 「已消失文件」按删除前文件大小累加，是可验证的文件逻辑空间变化，不是磁盘卷剩余空间测量。官方 CLI 是否移除历史 rollout 由执行后验证决定。
- 扫描结果和文件头保存在进程内缓存；搜索、排序在前端完成，不重新读取 JSONL。需要排查数据不同步时，可在“设置与诊断”中重新扫描；重新扫描会取消旧扫描。取消或扫描失败时禁止删除。扫描诊断移至“设置与诊断”的独立弹窗，每页 25 条、弹窗内滚动；最多提供 1,000 条明细并显示总条数。支持按类型和路径/会话名搜索，已确认关联的记录可“定位会话”后按正常流程清理。主页面不再展开诊断长列表。

## 预览边界

已验证 `history_mode=paginated`，使用 `thread_history_1.sqlite` 中 `thread_items` 与 `thread_turns.final_agent_item_id`。每页检查最多 40 条用户/助手记录，每条最多取 65,536 字符；仅显示用户消息、`phase=final` 或被最终回复 ID 指定的助手消息。超过限制的用户/已知最终消息显示占位。不将工具结果、reasoning 或 commentary 当最终回复。数据库没有已知结构时显示错误，不悄悄全量读 JSONL。

旧版 JSONL 每次最多读 4 MiB，单条解析最多 256 KiB，跨页跳过超大行，助手缺少 `final` 标记时隐藏。旧版可能出现空页，也可能缺少未标阶段的回复；GB 级单条记录需要多次翻页才能越过，第一版不支持快速跳转。历史数据库超过单条上限的文本也会省略。预览不是完整聊天导出。

内容仅通过 `textContent` 放入页面，无 Markdown/HTML 执行；图片数据不会作为媒体返回。页面 CSP 禁止内联脚本和外部资源。

## 删除与安全限制

只执行参数数组 `codex.exe delete --force <UUID>`，`shell=False`，将被选数据目录明确传给 CLI 的 `CODEX_HOME`。CLI 依次从显式路径、PATH、桌面版动态安装目录发现，并检查版本和 `delete --force` 帮助能力；不执行 `.cmd/.bat` 包装器。找不到能力时只读。

删除计划有效期 5 分钟、单次使用，不限制所选会话数量。POST 校验 Host、Origin、CSRF 及明确确认标记；服务内串行执行，阻止重复请求。执行前重读元信息并重新扫描关联文件，任何文件新增、变动、共享、路径变化均要求重新确认。每条命令前再次检查目标及其已知子会话的占用锁。已知子会话纳入同一计划、空间统计、当前会话保护和执行后验证；父子关系变化会使旧计划失效。

执行后检查线程元信息、已知历史索引表和原文件是否仍存在。退出码为零也可能报告「部分完成」。不直接改数据库、不删除残留、不迁移、不压缩图片、不 VACUUM、不复制大备份、不修改项目、worktree、凭据或 Codex 配置。

采用**按会话检查的在线清理**。本机 Codex Desktop 通过 stdio 启动 app-server，没有公开可连接的 daemon 控制 socket，因此未把另启服务的 `notLoaded` 错当成真实空闲。运行状态改为读取官方 `thread-writer-locks/<UUID>.lock` 的 Windows 字节范围锁：用只读句柄、非阻塞共享锁探测，立刻释放，不新建、删除或改写锁文件。列表约每 6 秒更新，删除前即时重检。

- **未占用**：已验证的锁协议下，没有正在持有的独占写入锁，可进入删除计划。
- **占用中**：Codex 持有该会话，可能正在运行，也可能只是仍被加载；不是“正在生成”的精确状态。仅保护这个目标及其父级删除计划，不阻止其他会话清理。切换页面不保证释放写入锁，工具不会强制卸载会话。
- **状态未确认**：无权读取锁、锁目录异常或 CLI 版本未验证，该目标禁止删除。

预检查只是瞬时快照；检查到执行之间若目标被重新占用，最终由官方 CLI 自身获取独占锁并拒绝冲突。**目前锁协议仅对 `codex-cli 0.154.0-alpha.6.2` 启用**，升级后默认禁止删除，需重新进行隔离验收再适配。不会为了删除而停止 Codex、释放其持有的锁或强行中断目标。

实现依据：[官方写入锁协调器](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/writer_lock.rs)、[官方删除实现](https://github.com/openai/codex/blob/main/codex-rs/thread-store/src/local/delete_thread.rs)。当前上游代码仅用于了解机制，本机 CLI 的隔离实测才是本版本兼容性依据。

## 实际调查与验证

2026-09-16 在本机 Windows / Python 3.13 上验证：

- `codex-cli 0.154.0-alpha.6.2`，动态发现桌面版 `bin/<版本目录>/codex.exe`；验证 `delete --force <UUID>` 能力。
- 实际生成并检查 app-server JSON Schema：`thread/list` 支持来源筛选、归档分页、`useStateDbOnly`；存在 `thread/loaded/list`。尝试只读 `app-server proxy` 后 8 秒未返回初始化响应。本版因此直接使用已核实 SQLite 元信息，并不启动新 app-server 触发修复/迁移，也不声称拿到了官方实时任务状态。将来版本需重新验证字段语义。
- 已验证 `state_5.sqlite`、`thread_history_1.sqlite`、`session_meta` JSONL（含 ordinal）、归档目录，以及本机实际 `session_index.jsonl`。索引文件仅用于调查，运行时不依赖它覆盖数据库标题。
- 真实数据只读扫描：当时识别约 **1,014 个用户主对话、1,030 个内部记录**，已确认独占 JSONL 约 **21.65 GiB**；数字随 Codex 运行变化。部分元信息指向已不存在文件，明确标记“文件缺失”，允许通过官方 CLI 清理残留条目；缺失文件不计入释放空间。无法读取、路径越界和归属冲突仍阻止删除。
- 对 6.02 GiB、3.80 GiB、1.40 GiB 三个大对话的预览请求实测约 **15–25 ms**（本机热缓存、首个预览页，不代表所有设备）；后两个会话各聚合了 3 个文件。没有完整读入 GB 级会话。
- 实际 Chrome 浏览器检查列表、真实预览、选择、删除阻止、搜索空状态、排序、内部视图、设置与 HTML/脚本注入夹具；未发现 JavaScript 错误。截图与结果存于 `.investigation/`（本机证据，包含私人标题，不应发布）。
- 删除成功、失败、超时、残留、当前会话保护、共享文件、变更文件、重复提交等用临时数据和模拟 CLI 验证。另外用本机官方 CLI 对独立临时目录的测试会话实测：持锁时拒绝删除且文件完整，释放锁后删除成功；期间真实 Codex 一直运行。**未删除、改写或迁移任何真实会话；未退出 Codex。**

运行自动测试：

```powershell
python -m unittest discover -s tests -v
```

浏览器回归脚本 `tests/browser-check.cjs` 是开发工具，可使用现成 Playwright 安装。设置 `PLAYWRIGHT_MODULE` 指向其模块路径、`CLEANER_URL` 指向已启动服务后运行；它不会点击真实删除执行按钮。日常使用完全不需要 Node.js/Playwright。

兼容性基线是上述本机版本；Python 3.10 仅遵循语言/API 兼容编写，未在本机另装 3.10 实测。暂不实现内部图片瘦身、存储迁移、自动清理、实时任务状态协议连接或完整聊天客户端。

官方 CLI 隔离契约验证（只会删除脚本自己创建的临时测试会话）：`python tests/probe_official_delete.py`。

文件缺失清理：删除计划列出已确认缺失的路径；不把无法读取当作不存在。若缺失文件在确认后重新出现，计划失效，须刷新重新确认。官方 CLI 清理后复核元信息与历史索引；全部文件原本已缺失时，验证成功的释放量为 0 B。

项目分组模式下显示左侧项目导航：可搜索项目名/路径，快速查看各项目会话数和占用，点击只自动展开并跳转到该组，不自动选择会话；点击会话标题才显示详情。滚动列表会更新导航中的当前位置；退出分组模式时隐藏导航。


### 界面语言

右上角可切换中文 / English，浏览器记住选择；切换不会清除筛选、勾选和已加载的预览。
会话标题、消息正文、项目名和文件路径保留原文；外部 CLI / 系统的原始错误不作机器翻译。

语言资源位于 `web/locales/zh-CN.json` 和 `web/locales/en.json`，使用相同翻译键和 `{name}` 插值。
`web/i18n.js` 负责资源加载、语言偏好、绑定更新和单复数选择；静态 HTML 使用 `data-i18n`，动态文案使用 `msg(key, values)` 与 `uiText`。
已有后端中文消息通过目录模板适配，不改变用于判断删除状态的原始值。展示用户内容时使用 `content` / `rawText`，避免把会话原文误当作界面文案。
新增文案需同步更新两份 JSON；测试检查键、插值参数和 HTML / JS 引用的一致性。
